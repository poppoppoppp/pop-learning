这里记录的是：

> 教学系统自己的 Bug、修复和版本变化。

不把导师系统的失败写成用户能力缺陷。

# V1.1 — 2026-09-03

## SYSTEM BUG 001 — 冷启动后仍然堆叠陌生术语

### 测试现场

新开对话后，系统成功：

- 找到 GitHub 能力地图；
- 读取 `CURRENT_STATE.md`；
- 识别 ONNX 为 `EXPOSED`；
- 知道计算图、Tensor 不能直接作为 Safe Anchor；
- 主动开始教学；
- 主动设计验证。

### 失败现象

虽然目标概念 ONNX 被正确检查，回答草稿仍然引入了多项未经验证的技术概念，例如：

- PyTorch
- Python 环境
- CUDA
- 模型参数
- ONNX Runtime
- NPU
- 推理引擎
- `.pth`

这些概念没有全部经过能力地图检查。

### 根因

V1 的 `SCAN` 只写了原则：

> 扫描助手准备使用的技术词。

但没有形成真正的“输出前强制门禁”。

系统知道规则，却仍可能在生成过程中继续堆术语。

### 修复

V1.1 增加：

1. `SCAN INPUT`
2. `BRIDGE PLAN`
3. `DRAFT`
4. `SCAN OUTPUT`

`SCAN OUTPUT` 将草稿中的知识型概念分成：

- SAFE
- TEACH-NOW
- DEFER

如果草稿依赖未知概念解释未知概念：

> 草稿必须重写。

## SYSTEM CHANGE 002 — 单层教学

新增规则：

如果 Safe Anchor 到目标知识之间还有多个未验证前置层级：

> 默认不一次跨完。

一次只推进一个关键前置层级，或一小组不会互相制造新依赖的紧密知识。

---

## SYSTEM CHANGE 003 — 原子命题能力状态

不再优先使用：

`整个概念 = 已掌握`

改为尽量记录具体已验证命题。

例如 ONNX 可以分别记录：

- 基本目的
- 为什么需要转换
- 导出与实际运行的区别
- 是否能够迁移到其他项目

用户证明哪部分，就只升级哪部分。

---

## SYSTEM CHANGE 004 — 类比退出机制

重要类比使用：

`类比 -> 相似点 -> 不相似点 -> 回到真实概念`

防止用户最终只记住一个方便但残缺的比喻。

---

## SYSTEM CHANGE 005 — 系统 Bug 与学习证据分离

导师系统本身的错误进入：

`system/CHANGELOG.md`

用户的真实能力证据继续进入：

`evidence/LEARNING_LOG.md`

两者不得混淆。
